# Review

Review my notebook (the open one, or the one I mention) like a senior analyst reviewing a junior's work, but **teach, don't fix**.

1. Read the notebook, `docs/DECISIONS.md` and the project brief.
2. Find the 3 to 5 most important issues, in order of impact: wrong or unsupported conclusions, data leakage or bad cleaning choices, charts that mislead, code that would break on re-run, unclear explanations.
3. For each issue: point to the cell, then ask me a question that leads me to see the problem (do not state the fix). For example: "In cell 7, what happens to the listings with no price before you compute the average?"
4. Mention one thing that is done well, and why it is good.
5. Ask me which issue I want to tackle first. Only show a fix if I ask for it.

Do not edit any files during the review.
